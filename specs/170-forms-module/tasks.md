# Tasks: Forms — a form builder whose forms are placed on pages as Page Builder blocks

**Input**: Design documents from `specs/170-forms-module/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Tests**: REQUIRED (Constitution III, SC-001). In every phase the test tasks come first; run each and
see it fail **for the stated reason** before starting the task that turns it green, and record under
the task which tests were seen red.

**Organization**: by user story in priority order. Phases 3–7 (US1–US5, all P1) are the MVP. Phase 2
carries what every story stands on: the four entities, the migration, the composition skeleton, the
tenancy guard and the static renderer of the block.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: parallel with its neighbours **inside its phase** (different file, no unfinished
  dependency in that phase).
- **[US#]**: the user story of `spec.md`. Setup, Foundational and Polish tasks carry none.

## Path conventions

- Module: `packages/modules/forms/` — `src/manifest.ts`, `src/backend/` (all composition in the single
  `src/backend/index.ts`, one delimited section per area), `src/migrations/`, `src/admin/`; `i18n/` and
  `docs/` at the package root; unit tests beside their subjects.
- Backend tests: `backend/test/contract/forms/`, `backend/test/integration/forms/`.
- Storefront tests: `storefront/test/forms/`, `storefront/test/ssr/`.
- Targeted runs (prefix every shell with `export PATH=~/.nvm/versions/node/v22.22.2/bin:$PATH` on the
  owner's machine):
  - `pnpm --filter @endora-commerce/contracts run test`
  - `pnpm --filter @endora-commerce/mod-forms run test`
  - `pnpm --filter @endora-commerce/cms-components run test`
  - `pnpm --filter @endora-commerce/page-builder-admin run test`
  - `pnpm --filter backend exec vitest run <path>` (contract/integration need `pnpm run dev:infra:test` and `TEST_DATABASE_URL`)
  - `pnpm --filter backend exec vitest run --config vitest.unit.config.ts <path>` (service-free unit files)
  - `pnpm --filter storefront exec vitest run <path>`, `pnpm --filter admin exec vitest run <path>`

## Standing rules for every task

1. **Read before writing** the routed convention for what the task does (`AGENTS.md` § *Where the rest
   of it lives*): `module-composition.md` before any port/route/worker/subscriber/boot hook;
   `module-activation.md` before any gate; `module-migrations.md` before T015; `module-admin-surfaces.md`
   before permissions, palette, nav; `module-i18n.md` before any string; `module-documentation.md`
   before Phase 13; `release-intent.md` before changesets; `backend-test-suite.md` before running
   backend suites; `building-packages.md` when a type-check and a test run disagree.
2. **Touch nothing outside `packages/modules/forms/`** unless `contracts/foreign-module-changes.md`
   lists it or rule 5 names it. Otherwise stop and report.
3. **Rebuild a package you edited** (`pnpm --filter <pkg> run build`) before running another
   package's tests against it.
4. **Regenerate generated files, never edit or hand-merge them**: `composer:generate`,
   `manifests:generate` (+ `pnpm install --lockfile-only`), the cms-components CSS build, the OpenAPI
   baseline.
5. **Ledgers updated in the change that needs them**: `packages/contracts/src/errors.ts` +
   manifest `errorCodes` + `errors.<CODE>` in both bundles, in the change that adds the code's first
   raise site; `backend/test/fixtures/error-code-routing/reference-ledgers.ts` (`MINTED_ERROR_CODES`);
   `backend/test/helpers/package-entities.ts` (new entities).
6. **Never** put answers, consents, `submitter_email`, `search_text` or note bodies into an audit
   state, a log line, a queue payload or an event other than FR-064's shared answers.
7. **Every read of `form_entries` goes through the tenancy guard**; widening only through
   `withSystemScope` / `enterSystemScope` with a non-empty reason.
8. **Never run `db:fresh`, `db:reset`, `setup` or `module:*`** against a database you did not create
   for the test.
9. **Commits** (when the owner asks): conventional style, `git commit -s`, no AI trailer; never on
   `master`.
