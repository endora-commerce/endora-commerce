# Contract: Foreign schema refusal (OD-17) and the extensible-table promise

## 1. Runtime guard (authoritative for instances)

`guardExternalMigration(cls, context)` in `packages/platform/src/db/foreign-schema-guard.ts`, applied
by `configuredMigrationsFrom` to every entry with origin `external`. It returns a subclass with the
same `name` (research R-10, spike-verified) overriding:

- `addSql(sql)` and `execute(sql, params)` — stringify (knex builders via `toQuery()`), classify,
  refuse or pass through;
- `getEntityManager()` — returns the fork wrapped so its `flush` refuses changesets whose
  `meta.tableName` is foreign, **and** so its non-flush shortcuts (`nativeInsert`, `nativeUpdate`,
  `nativeDelete`, `insert`, `insertMany`, query builders, `execute`) are classified the same way
  (OD-178-3; scope amended by D-291 R-A1).

`context`: `moduleId`; `ownTables` = tables mapped by the package's `entities` ∪ tables its own
migrations `create` **that no other module's entity maps**; DDL on a table the same migration
creates is a declaration, not a write. Tables created by the module's earlier migrations are found
by an in-memory dry run of its migrations (`execute` answering no rows), lazily at the first guarded
migration, never at boot; a table the dry run cannot see is foreign (fail closed) — D-291 R-A2.
`declaredHosts` with their own `x_<module>_` prefix; `exemptions` (§3).

Classifier `sqlWriteTargets(sql)` (`packages/platform/src/db/sql-statement-targets.ts`, regex, no
TypeScript dependency): targets of `alter table`, `create [unique] index … on`, `drop table|index`,
`comment on (table|column)`, `create trigger … on`, `create rule … to`, `insert into`, `update`,
`delete from`, `truncate`, `merge into`; scans inside `do $$…$$` bodies, `create function` /
`create procedure` bodies, and PL/pgSQL `execute '…'` strings read as SQL (D-291 R-A1). `drop
index` is resolved to its table through `pg_indexes` at run time.

Verdict per target table `t`:

| `t` | Allowed |
| --- | --- |
| in `ownTables` | yes |
| kernel-owned (`PLATFORM_ENTITIES` tables, `mikro_orm_migrations`) | yes (R2 parity) |
| a declared host, statement is `update t set` and every set column starts with `x_<module>_` | yes |
| exempted (module, class, table) | yes |
| anything else | refuse `ForeignSchemaWriteError` (`foreign-schema-write`, package, migration, table, statement head) |

Reads are not judged. The run rolls back.

## 2. Parity test

`backend/test/unit/db/sql-write-targets-parity.test.ts`: over every first-party migration file,
`sqlWriteTargets` and `sqlTableAccesses(…, { ddl: true })` (writes only) yield equal table sets per
file; any difference is a red finding to fix in one of them.

## 3. Exemptions

`FIRST_PARTY_FOREIGN_WRITE_EXEMPTIONS: readonly { moduleId; migration; table }[]`, generated by
`composer:generate` from `backend/scripts/ledgers/migration-foreign-writes/*.ts` (file → class name
by the naming convention) into `packages/platform/src/migrations/foreign-write-exemptions.generated.ts`,
exported on `./migrations`. Stale when the ledger changes; `overlay:check` verifies freshness like
the baseline list. An R2 entry retired from the ledger leaves the list in the same merge request.

## 4. `check:extensible-tables` (static, `quality` job)

Script `backend/scripts/check-extensible-tables.ts`. Population: migrations of every module that owns
an extensible table (derived from `CUSTOM_FIELD_HOST_BINDINGS` and `buildTableOwners`).

Findings:

- `extensible-table-rebuild` — on an extensible table: `drop table`, `alter table … rename to`,
  `create table … as select … from <t>`, `insert into … select * from <t>`, `select * into`;
- `binding-owner-mismatch` — a binding's `ownerModuleId`/`table` disagrees with the entity owner
  map (FR-012);
- no ledger: every acceptance is derived. A legitimate rebuild is a core design change that must
  carry the `x_*` columns forward and is resolved by changing the migration, not by an entry.

Obligations (check-estate.md): inventory row in `check-inventory.md` and
`backend/test/unit/scripts/check-inventory.test.ts`; estate entry in
`packages/cli/src/check/estate.ts` (`scope: 'package'`, `host: 'built'` — it reads one package's
migrations directory and the published bindings); companion test with red proofs per finding; exit 2
on an empty or short walk; one `read:` line via `backend/scripts/lib/read-size.ts`; a recorded read
size measured in a clean tree.
