New port `PriceBookRowWritePort` (container name `priceBookRowWritePort`, exported as `PRICE_BOOK_ROW_WRITE_PORT`, owner `price_lists`): a module — an ERP or PIM connector — can now write the rows of one product in one non-base price book (a customer-group, organization, catalogue or sale book) without an admin HTTP call. `replaceBookRows(bookId, productId, { product: BasePriceTier[], variants?: Record<variantId, VariantRowWrite | null> })` replaces the product's fixed tiers and the rows of the named variants and answers `BookProductRows`; `removeBookRows(bookId, productId)` removes them (a no-op when there are none); `bookRows(bookId, productId)` reads them, or `null`. Only rows the write shape can say are the port's: a row an administrator entered that it cannot say — a product-level percentage or amount, an adjustment limited to a quantity range — is neither replaced nor removed and keeps pricing; `bookRows` reports it with `complete: false`, and a tier that would overlap it, even one starting at the same quantity, is refused with `409 PRICE_BOOK_ROW_OVERLAP` naming it, never written over it. Each write goes through the admin row batch's rules and command, audited as `price_list.book_rows_set` or `price_list.book_rows_remove` with the caller's actor — the entry holds names, counts and a `valueChangeId`, never a price or a quantity; the prices go to the book's own price-change history (`price_list_value_changes`), written in the same Command — and bumps the pricing generation once, naming the book and the product; a write that changes nothing writes nothing. The port creates no book and changes no header. Base books are refused with the new error code `409 PRICE_BOOK_BASE_BOOK` (write base prices through `priceBookWritePort`, which is unchanged) and expired books with `409 PRICE_BOOK_EXPIRED`; both codes are added to `ERROR_CODES`, with the new schemas `bookProductRowsWriteSchema` and `bookProductRowsSchema` and the type `VariantRowWrite`. Additive (issue #1028).
