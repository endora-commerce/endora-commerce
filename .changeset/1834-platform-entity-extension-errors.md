**Side-table entity extensions: declared, verified at `migrate` and at boot** (issue #1834, `specs/187-side-table-extensions/`). A module that keeps a table of its own whose single-column primary key is a cascading foreign key to an extensible host's primary key declares it in its manifest's `extends` (see `@endora-commerce/contracts`), and the platform holds it on identical terms for core modules, installed packages and overlay modules:

- **Composition** — `resolveEntityExtensions` (on `./db`) refuses a host that is not extensible (`host-not-extensible`, listing the nine), a host owner outside the module's dependency closure (`host-not-a-dependency`), a module declaring on its own aggregate (`self-extension`) and a table declared twice (`duplicate-table`). The manifest registry, the static registry every `module:*` command builds (`module:install` exits 65) and the migration merge all ask it. `ENTITY_EXTENSION_HOSTS` maps each `<ownerModuleId>.<EntityClassName>` to its `EntityExtensionHost`.
- **ORM discovery** — after the declared-columns rule, every ORM initialisation holds each custom-field host binding to the class mapping its table (`host-binding-mismatch`) and each declared table to an entity of the declaring module (`table-not-owned`), keyed by exactly one property (`primary-key-not-single`) of the host key's type (`primary-key-type-mismatch`), with the tenancy its host admits (`tenancy-mismatch`): a side table of `organizations` is `@GlobalEntity()` or `@OrgScoped()` keyed by its primary key; of an `@OrgScoped` host, `@TransitivelyScoped('<HostClass>', '<pkProperty>')` — never a copied `organization_id`; of a global host, `@GlobalEntity()`; of a rule-scoped host, `@RuleScoped()`. `mikroOrmConfigFrom` takes `entityExtensions` (defaulting to what the merge resolved) and `coreEntityOwners`.
- **The database** — one catalog query, inside the `migrateUpVerified` transaction after D2's verifier and read-only in `composeApp` after the ORM opens: a declared table must exist (`table-missing`) with a foreign key equal to its primary key referencing its host's primary key (`foreign-key-missing`) and `on delete cascade` (`foreign-key-not-cascade`). A finding rolls the `migrate` run back, or stops the boot, with `EntityExtensionDriftError` naming every finding.
- **Undeclared side tables** — a table whose primary key is a foreign key to a host's and which nothing declares is logged at `warn`: `undeclared-entity-extension` when a composed module's entity maps it (naming the `extends` entry to add), `unowned-entity-extension` when none does. **In this release `ENTITY_EXTENSION_UNDECLARED_POLICY` is `'warn'`; from the next release an undeclared side table a composed module owns is refused at `migrate` and at boot.** Add the declaration now. An unowned one stays a warning.
- **`module:schema-extensions`** — `list` prints an `Entity extensions (side tables)` section (and `--json` an `entityExtensions` key) with each side table's module, origin, host, table, constraint and status (`verified`, `violation:<rule>`, `undeclared`, `unowned`), derived on each run and never written to the ledger; `audit-packages` prints one verdict per installed package's `extends` entry without a database; `drop` on a module with only side tables says they go with `module:uninstall --hard`.

A composition that declares nothing and keeps no such table pays one catalog query at `migrate` and at boot, and nothing changes for it.
