**Route a buyer's quote request to a representative inside the submission** (issue #1906). The buyer's create-and-submit (`POST /api/v1/quote-requests` and every `RfqCustomerPort.createForCustomer` caller) and *Submit again* (`POST /api/v1/quote-requests/:id/resubmit`) are now Commands, `quote_request.create` and `quote_request.resubmit`, run on the Command Bus (Principle XIII), and are declared hookable for both phases as `QUOTE_REQUEST_HOOKABLE_ACTIONS.create` and `.resubmit`. Their audit entries are the ones the hand audit recorded — same action, actor (impersonation included) and `{ status, itemCount, salesChannelId }` state — and the request, its lines, revision, history entries and notification records still commit together; `rfq.created.v1` is announced once on the create's commit, and a resubmit still announces nothing. Without a registered hook nothing changes.

A `beforeCommit` hook sets the assignee with `data.assign(adminUserId)`: the module checks the administrator, runs its own `quote_request.assign` as a child Command — a second audit entry, `source` the hook's module id — and records the operators' notifications of the submission again, so they go to that assignee. The outbox row names the assignee at commit.

**One assignee rule everywhere.** An administrator named as a quote request's assignee must be active, hold `rfqs:handle` and reach the request's Organization (their admin scope; for a sales representative the representative rule). `POST /api/v1/admin/quote-requests/:id/assign` and `quoteRequestCommandPort.assign` now refuse anyone else with `422 RFQ_ASSIGNEE_NOT_ELIGIBLE` before writing (previously any id was stored); clearing with `null` stays allowed. Inside a buyer's submission the refusal carries the token `submission`, worded for the buyer. Saving an offer, approving and cancelling still make the acting administrator the assignee, as before. The module now reads `organizations`' `adminTenantScopePort` for the assignee's reach. The buyer's other writes (`patch_draft`, `respond_to_revision`, `convert_to_order`) keep their hand audit and are not hookable.
