`endora new instance` scaffolds the backend under a supervising parent (issue #596), so a backend that is alive but no longer answering is restarted, as the storefront has been since #152. The instance gains `backend/scripts/supervise.mjs`, carried byte for byte from the platform repository's copy (the CLI's build writes it into `dist/backend-supervisor.mjs`, and `prepack` refuses a tarball without it). `deploy/Dockerfile.backend` now ends in `CMD ["node", "scripts/supervise.mjs", "dist/index.js"]`, and the `backend` service of every compose example sets `init: true` and `stop_grace_period: 30s`, which leaves the supervisor's 25 s kill grace room for the queue consumers to drain. The supervisor probes `/api/v1/_health` and counts any HTTP status as an answer; it is tuned with the optional `BACKEND_SUPERVISOR_*` variables. `backend-migrate`, `backend-install` and a `node dist/worker.js` worker tier keep their own commands, unsupervised. The scaffolded storefront's `scripts/supervise.mjs` is the same file with the storefront's profile; its behaviour is unchanged. An existing instance copies the file and edits its Dockerfile and compose service by hand (*Upgrading an instance*, "A backend that stops answering is restarted").
