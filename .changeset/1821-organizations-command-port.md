**`organizationCommandPort` — every server-side write on an Organization** (issue #1821, `specs/186-aggregate-ports/` US1a). Another module, an overlay or an integration worker creates, updates, places in the tree, approves, rejects, blocks, unblocks and deletes an Organization, sets its custom-field values, allow-lists, credit-inheritance mode and sales representatives through the published port, with the ambient actor (the system actor under `withSystemScope`) and an optional `source` code recorded in the audit entry. Each method runs the Command its admin endpoint runs, with the same refusals; `create` answers an unknown sales channel `422 UNKNOWN_SALES_CHANNEL` as `organizationWritePort.create` always has. The sales channels of an existing Organization are not on the port yet. `organizationWritePort` and `organizationCustomFieldWritePort` are deprecated and delegate to it, writing the same entries as before.

The allow-list writes (`organization.allow_lists_replace`, `organization.allow_list_patch`) and the sales-representative assignment (`organization.sales_rep_assign`, `organization.sales_rep_unassign`) are now Commands: the change and its audit entry commit together, command hooks can see them, and the action strings and audit state are unchanged. Assigning a representative already assigned records nothing, as before. The HTTP API is unchanged.

The customer's approval and rejection e-mails are now sent by this module's subscriber of `organization.status_changed.v1`, after the change commits, so they also go out when an approval runs inside another Command. The event gains `notifyCustomer: boolean` (`false` for a rejection with `notifyCustomerEmail: false`, and for a block or unblock).

For code that builds the services by hand: `OrganizationRestrictionService` and `SalesRepAssignmentService` take the Command Bus as their second constructor argument, in place of the audit port; `OrganizationWriteService` takes `{ commands, lookup }` and `OrganizationCustomFieldWriteService` the aggregate port; `OrganizationModerationService.approve` / `reject` / `block` / `unblock` take `expectedVersion` as optional, and no longer send the notice themselves — subscribe `notifyStatusChanged` to the event to send it.
