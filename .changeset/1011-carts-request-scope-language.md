**The storefront basket's scope language is the channel language `Accept-Language` asks for, read as a q-weighted list** (issue #1011). Every storefront route that resolves the basket (`/api/v1/cart` and its `items`, `coupon` and other sub-routes) took the header's first tag alone as the language the basket's lines are judged and named in, so `Accept-Language: en;q=0.2, pl-PL;q=0.9` asked about English and `de-DE, pl;q=0.5` about the channel default, and adding a product available only in Polish was refused with `404`. The language is now resolved through `requestScopeLanguage` from `@endora-commerce/contracts`, as the catalogue does since #397: the tags in descending `q`, each matched against the channel's languages (exactly, then by base language), the first one the channel offers winning, else the channel's default. The language messages are worded in is unchanged. A request without the header behaves as before. And an anonymous visitor's first add to a basket (`POST /api/v1/cart/items` without a usable basket cookie, which mints a new basket token) dropped the request's language altogether and was always judged in the channel's default language; it is now judged in the same language as every other basket request.
