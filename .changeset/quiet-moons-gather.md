A module publishes the row types of the entities it owns, on `./test-support`

The second instance of the same hard stop. A deployment's entity index takes each module's
registered `entities` **array** from the published `./backend` subpath and then had to name the
entity **class** by a relative path into the package's `src/`, because a module package publishes
`entities` and no named entity class (D-168). 43 such reaches into these seven, every one an
`import type` and therefore invisible to every runtime instrument — and every one fatal to the
compile the moment the package's directory is not there.

`export type` erases, so nothing is evaluated a second time and no value reach into a sibling's
sources is created.
