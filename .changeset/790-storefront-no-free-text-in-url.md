Storefront: no free text from the URL reaches the page (issue #790). Only the `storefront` application changes, which is in the Changesets `ignore` list; no published package's emitted code moves. After *Save to list*, the cart's `?listAdded=` carries the list's id and the banner reads the name of the buyer's own list, so a crafted link shows nothing. The quick-order preview no longer travels in the URL: it is kept in one httpOnly cookie the storefront writes itself, at most about 3 000 characters so the default nginx buffers in front of the storefront never refuse a request or a response, bound to the session, and cleared once the cart or quote request is built and on sign-out or session expiry. An import too long to keep asks the buyer to split the file; an add or an edit that would overflow it asks them to build what they have first. A partial cart build carries only counts in the URL and keeps exactly the lines the cart did not take in the preview, each with the minimum it missed, ready to correct and build again; each such line is named by its product name and SKU, with the packaging unit where the minimum is one. On the cart, a quantity carried back after a refused edit is kept only when it is a whole number. The deployment's example nginx config gives the storefront larger proxy buffers as extra headroom. After a quote build the page reads the request's reference from its id, and the quick-order search text is capped at 120 characters.
