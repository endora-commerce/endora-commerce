`endora new module` writes its tests beside their subjects instead of under `test/unit/`: `src/backend/manifest.test.ts` (was `test/unit/manifest.test.ts`; not `src/manifest.test.ts`, which the manifest generator refuses as a sibling of the root manifest) and, with `--admin`, `src/admin/index.test.ts` (was `test/unit/admin-contributions.test.ts`), which is type-checked by a new `tsconfig.ui.test.json` (the Node types it reads bundles with, in a program of its own) while `tsconfig.ui.json` keeps `types: []` and now excludes the tests — the layout issue #566 gave the existing modules. The emitted `vitest.config.ts` collects `src/**/*.test.ts` only. A module package has no `test/` directory, and a test there is in no type-check program — `tsconfig.json` includes `src/**/*` alone. A package scaffolded earlier is unaffected; to have its `test/unit/` files type-checked, move each under `src/` beside its subject (never as a sibling of `src/manifest.ts`), re-point its relative imports, and drop `test/**/*.test.ts` from the `include` list in its `vitest.config.ts`.
