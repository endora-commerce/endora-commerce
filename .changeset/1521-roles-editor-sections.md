The Roles editor (`/admin-roles`) is one card of sections instead of a warning banner and a bordered box per module (issue #1521, UX audit 2026-11-17, SHELL-13; DS-03). The card's header names the role and carries an outlined *Delete role*; *Details* holds the code, the display name and the two-step verification switch; *Permissions* holds a *Full access* switch, whose warning shows only while it is on, then a filter and one collapsible section per module. Each module section is named by the module's own name (`module.name` in its bundle, words from the id otherwise), shows how many of its permissions are selected and has a checkbox that selects or clears them all. A permission reads by its label, with its code, what it needs and which modules keep it available as one muted second line. The role list marks the open role with a muted fill instead of a filled primary block, Save is disabled while a save is in flight, and opening another role, or leaving the screen, with unsaved changes asks first. What a role grants is unchanged.

Translation keys removed from both `en` and `pl`: `core` `adminRoles.dependencies.description` (now `adminRoles.dependencies.hint`, shortened), `adminRoles.wildcardPrefix`, `adminRoles.wildcardSuffix`, `adminRoles.wildcardTitle`. New `core` keys: `adminRoles.dependencies.hint`, `adminRoles.discardChanges.confirm`, `adminRoles.filter.label`, `adminRoles.filter.placeholder`, `adminRoles.group.count`, `adminRoles.group.selectAll`, `adminRoles.permissions.count`, `adminRoles.section.details`, `adminRoles.wildcard.hint`, `adminRoles.wildcard.onWarning`. Changed parameters: `adminRoles.dependencies.add` takes `{label}` (was `{code}`), `adminRoles.requires` takes `{permissions}` (was `{codes}`), both now given permission labels. Shortened: `adminRoles.owners`, `adminRoles.wildcardLocked`, `adminRoles.dependencies.title`. A deployment that overrides a removed or changed key should update its override.
