Command middleware declarations (`specs/189-command-middleware/`, issue #1840). `ModuleManifest` gains an optional `commandMiddleware: { id, phase: 'admit' | 'observe', actions: '*' | string[], timeoutMs? }[]`, validated by the new `CommandMiddlewareDeclarationSchema`; `defineModuleManifest` applies `assertCommandMiddlewareRules` (one id declared twice, a `timeoutMs` above `COMMAND_ADMIT_TIMEOUT_MAX_MS` / `COMMAND_OBSERVE_TIMEOUT_MAX_MS`, a duplicate or covered filter entry) and now refuses a manifest that carries an `origin` key, which a module cannot declare. New exports: `COMMAND_MIDDLEWARE_PHASES`, the time-limit constants, `COMMAND_OBSERVE_MAX_IN_FLIGHT`, `commandActionFilterRe`, `commandActionFilterMatches`, `commandActionFiltersOverlap`, and `MODULE_ORIGINS` / `ModuleOrigin` (`core`, `deployment`, `package`), the derived trust tier of a composed module. `DivergenceKind` gains `'command-middleware'` with its detail, and `DeploymentDivergenceDeclarationSchema` gains an optional `commandMiddlewareOrder: string[]` (two or more module ids). The declaration schema is strict, so a `divergence.ts` that writes `commandMiddlewareOrder` is refused by an older platform — which is correct, since that platform would run without the order. `ERROR_CODES` gains `COMMAND_ADMISSION_TIMEOUT`, `COMMAND_ADMISSION_FAILED` and `COMMAND_MIDDLEWARE_REENTRY`.
