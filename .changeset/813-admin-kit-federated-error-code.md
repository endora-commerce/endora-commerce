**Breaking:** `useAuth()` gains `federatedSignInError: FederatedSignInErrorCode | null`, and the `?error=` a federated sign-in leaves on `/login` no longer arrives in `lastLoginError`. `AuthProvider` passes on only a value that parses with `federatedSignInErrorCodeSchema`; any other value, a sentence an older `mod-mfa` sent included, arrives as `'sign_in_failed'`, so the raw value is never available to print. A login screen that rendered `lastLoginError` to show a federated refusal now reads `federatedSignInError` and words the code itself. `lastLoginError` still carries the backend's answer to a password or second-step attempt and the session-expired notice. `useAuth()` also gains `lastLoginReason: LoginErrorReason | null` (the type is exported from `@endora-commerce/admin-kit/lib`). It is `'session_expired'` for the notice set when a signed-in session answers 401, and `null` otherwise. It is set and cleared together with `lastLoginError`, so a screen titles the session-expired notice from the reason instead of matching the message text. The next sign-in attempt clears all three (issue #813).
