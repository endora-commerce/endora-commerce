**Admin form extensions, the platform half** (`specs/193-admin-form-extensions/` WP-B, ruling D-300).

**Breaking change** (`specs/193-admin-form-extensions/` ruling D-300.13, as for #1835): `ModuleContext` gains two new **required** members, `fieldSets(entries)` and `fieldFormats(entries)`. Code that only calls a context the platform builds needs no change; code that constructs a `ModuleContext` object of its own (a hand-written test double) fails to type-check until it adds both methods.

- **Field sets' writers** — `ctx.fieldSets([{ set, writers: [{ on, mode, writes, project, ruleCheckOnly?, scoped? }] }])` lists the actions that write an owner's own field set, each with a pure projection from its hook data to the field values (`FieldSetRegistration`, `FieldSetWriter`, `FieldProjection`, `FieldScopedProjection` on `./kernel`). `ctx.fieldFormats([{ id: '<moduleId>.<name>', validate }])` registers a module format's server validator (`FieldFormatRegistration`).
- **Composition** — `ComposeModulesOptions` gains `formRegistry` and `forms`; the registry is sealed after the side-table loader registry and before the boot phase, and refuses, naming the module, field set, field and remedy: duplicate field sets and forms, unknown field sets, fields, forms, sections and controls, a form declared by a module that does not depend on the set's owner, writers registered by another module or on an action that is not hookable with `beforeCommit` (or a rule-check-only writer on a hookable one), `accepts-unenforceable`, unknown permissions, and every override refusal of `contracts/field-overrides.md` §3 — `override-not-accepted`, `hidden-required-field`, `default-on-hidden`, `default-type-mismatch`, `required-not-fillable` (a hidden field effectively required on a create form, D-300.12), `override-loosens-rule`, `override-contradiction`, `override-conflict`, `control-type-mismatch`, `format-without-validator`, `condition-foreign-field`, `foreign-override`, `override-owner-not-a-dependency`, `PackageFormOverrideNotGrantedError` and `InvalidFormOverrideGrantError`. An override naming a deprecated alias is warned (`deprecated-target`).
- **The field-rule check** — the Command Bus runs it first in a writer's `beforeCommit` phase, before every module hook and outside hook ordering, also on a rule-check-only writer no module may hook. It holds the present modules' tightened `validation`, `requiredWhen`, control formats and `writePermission` over the projection, skips buyer self-service writes — a customer acting for itself, or a Command that declares the new `buyerSelfService: true` (inherited by its children) run by a `system` or `customer` actor with no acting admin (D-300.3, D-300.10) — and is not retroactive: on an update only the fields the write set or cleared are held, and `requiredWhen` also when the write changed a field its condition reads (D-300.4, D-300.11). A violation is `422 FIELD_RULE_VIOLATION`, a forbidden change `403 FIELD_WRITE_FORBIDDEN`; the Command rolls back with no audit entry and no outbox row. An action no rule applies to is unchanged — its hook data is not even computed. `CommandHookRegistry` gains `useFieldRuleCheck` and `fieldRuleCheck`.
- **Buyer self-service is declared (issue #2027).** `Command` gains `buyerSelfService?: true`. Only an action a composed manifest lists in the new `buyerSelfServiceActions` may carry it: `CommandHookCompositionInput` gains `buyerSelfServiceActions` (derived by `buyerSelfServiceActionsFrom(manifests)` on `./composition`), two modules listing one action refuse the composition (`DuplicateBuyerSelfServiceActionError`), and the bus throws `UndeclaredBuyerSelfServiceActionError` before `run` for a flagged Command of any other action, so nothing is written. A worker, an import or a callback cannot opt out of field rules by setting the flag.
- **`fieldSlotHook(spec)`** on `./kernel` builds a slot module's `beforeCommit` hooks: no-op without a slice, `422 FIELD_SLOT_INPUT_INVALID` with paths under `extensions.<moduleId>`, `403 FIELD_WRITE_FORBIDDEN` for a changed key the actor may not write, and the changed names noted on the owner's audit entry.
- **`GET /api/v1/admin/effective-forms`** (`_lifecycle`, `requireAdmin()` with no code) serves every present form's effective fields, layered core → deployment code → operator (`formLayoutOverrideSource`, when registered), with an `ETag` and `304` on a matching `If-None-Match`, memoised per presence snapshot and operator-layout generation; `b2b:form-layout:changed` drops the memo, and a 60-second TTL bounds a lost subscription.
- `_lifecycle` declares `FIELD_RULE_VIOLATION`, `FIELD_WRITE_FORBIDDEN` and `FIELD_SLOT_INPUT_INVALID`, with `fieldRules.*` sentences in `en` and `pl`. The error envelope translates a `details[]` entry marked with the sentence it carries into the response language; unmarked entries are unchanged.
- New on `./composition`: `FormRegistry` and `formDeclarationsFrom(manifests, grants)`; `composeApp` gains `formOverrideGrants`, builds the registry and registers it as `formRegistry`.
