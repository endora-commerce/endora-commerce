New kernel port `AuditRedactionPort` (exported from `@endora-commerce/platform/kernel` with `AuditRedactionInput`, `AuditRedactionTarget`, `AuditRedactionResult`, `AUDIT_REDACTED_ACTION` and `AUDIT_REDACTION_MAX_IDS_PER_TARGET`), whose platform-owned container name is `auditRedactionService`, beside `auditLogService` (`composeApp` registers it together with its first caller, the customers retention sweep). `redact({ reason: 'anonymization', subject, targets, subjectActorAccountId })` erases an anonymised subject's audit history in place: every key of `stateBefore` / `stateAfter` is kept, UUID ids, ISO timestamps, booleans, `null` and short codes under code keys (plus the caller's `keepKeys`) are kept, every custom-field value and every other value becomes `"[erased]"`, and the IP address and user agent are erased on the rows the subject wrote for itself. It works in chunks of 500 rows with one `UPDATE` each, skips rows already erased, catches rows written during the run, and records one `audit.redacted` row per subject. It refuses a call with no target, an empty target, a non-UUID id or more than 1,000 ids in one target. `AuditPort` is unchanged. The implementation, `AuditRedactionService(emFactory, auditLog)`, is on the host-internal `./composition` subpath beside `AuditLogService`.
